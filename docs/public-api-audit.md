# Public API Audit (Phase 17)

Status: Phase 17 deliverable. Inventory method: `go doc -all` over every
package plus an AST-level check of exported struct fields and methods on the
consumer-facing types. Regenerable with `go doc -all <pkg>`.

## Scope and method

Every exported symbol of every non-test package was enumerated and
classified:

| Class | Meaning |
|---|---|
| REQUIRED | Exported because another package in the module composes it; load-bearing for the SDK to work at all |
| STABLE | Production-ready public contract; covered by the API contract test |
| PROVISIONAL | Usable, but the shape may still evolve before any v1 tag |
| INTERNAL | Test seam or composition detail that is exported for mechanical reasons (cross-package access, external `*_test` packages); not part of the recommended consumer API |
| INTERNAL-BY-MISTAKE | Should never have been public — fixed in this phase |
| TEST-SUPPORT | Exists only for tests of this module; not for consumers |

The generated package `github.com/Skryldev/suromesh/tl/gen` (47 files, 1,684 constructors, Layer
182) is classified as a block: **STABLE, schema-derived** — its surface is
dictated by the TL schema, regenerated by the frozen generator, and never
hand-edited.

## Suspicious symbols — detailed register

Every symbol below was individually reviewed. The rule applied was:
document first, change only with justification, prefer additive evolution.

### Fixed in Phase 17 (INTERNAL-BY-MISTAKE)

1. **`client.MessageBox`** — type with 23 unexported methods; the update
   state machine. No public API returns it and no code outside package
   `client` referenced it (verified by repo-wide search; external test
   references were comments only). Its presence in godoc suggested
   consumers could/should own update state, contradicting the architecture
   rule that the MessageBox is the internal sole ordering authority.
   **Action: unexported (`messageBox`).** Compatibility impact: none for
   obtainable objects — no external code could hold a `*MessageBox`.
   Regression: full suite green after rename.
2. **`github.com/Skryldev/suromesh/transport/wstest`** — an entire in-memory MTProto server
   double published at a public import path. Name says "test"; consumers
   could accidentally import a test double. **Action: moved to
   `github.com/Skryldev/suromesh/internal/wstest`** (same module, so all in-module tests
   `client`, `tests/*` compile unchanged after an import-path rewrite).
   Compatibility impact: removal of a test-support package; no consumer
   workflow used it; importers outside the module were never supported.

### Kept exported — classified INTERNAL (test seams)

These exist on `*Client` and are used by the external `client_test` package
(37 files, deliberately testing the SDK as an outside consumer — a Phase
9–16 property worth keeping). Converting the whole external suite in-package
to unexport six methods was considered and **rejected**: the
external-consumer test perspective is more valuable than six fewer godoc
entries. They are pinned by `tests/compatibility/api_surface_test.go` so
their behavior cannot drift silently.

| Symbol | Purpose | Risk |
|---|---|---|
| `(*Client).SeedRaw(...tl.Object)` | Seed the entity cache from raw TL objects (fake-server testing) | Misuse could poison resolution; documented as test-only |
| `(*Client).SeedEntities(*[]User, *[]Chat, *[]Channel)` | Typed seeding wrapper | Same |
| `(*Client).ClassifyMediaForTest(gen.MessageMediaClass) Media` | Canonical classifier entry for external tests | Pure function of its input; no risk |
| `(*Client).ResolveMediaLocationForTest(Media) (...)` | Location resolution for external download tests | Test-only |
| `(*Client).ClosedForTest() bool` | Terminal-state assertion | Read-only |
| `(*Client).ReconnectTransportForTest()` | Force transport reconnect (failure injection) | Deliberate disruption; test-only |

`(*Client).InputPeerFor(ctx, Peer)` is **not** in this list — it is STABLE:
it is the sanctioned bridge from a resolved `Peer` to `gen.InputPeerClass`
for raw `Invoke` use by advanced consumers.

### Naming / design consistency findings (audit, no changes required)

- Context placement: every network-facing consumer method takes
  `context.Context` as its **first** parameter (`Connect`, `SendMessage`,
  `GetDialogs`, `Upload`, `Download`, ...). The two exceptions are
  deliberate and documented: `Close()` (terminal barrier; must not be
  cancellable — standard Go convention) and `CatchUp()` (posts a
  synchronous catch-up request to the owning sync loop; it inherits the
  loop's lifetime and closes with the client, so there is no caller
  deadline to splice — documented in docs/cancellation.md).
- Naming: `GetX` (fetch: GetUser/GetChannel/GetChat/GetMessages/GetMe),
  `IterX` (paged iterator), `ResolveX` (may perform network resolution),
  `SendX` (mutations). Semantics match prefixes consistently; no
  `FetchX`/`LookupX` synonyms exist.
- Iterators: all four (`DialogIterator`, `MessageIterator`,
  `SearchIterator`, `GlobalSearchIterator`) share `Next() (T, bool)` +
  `Err()` conventions and caller-owned termination (see docs/iterators.md).
- Errors: all sentinel errors are `Err*`, all typed errors are `*TError`
  usable with `errors.As`; `ClassifyError`/`AsFloodWait`/
  `AsConnectionLost` are the string-free triage helpers. Documented in
  docs/error-contract.md.
- Zero values: `Config` zero value is invalid by design (`New` validates —
  `ErrInvalidConfig`); domain structs (`Message`, `User`, `Dialog`) have
  meaningful zero values as plain data.

## Compatibility policy going forward

- The STABLE surface may only grow additively before any v1 tag.
- The INTERNAL test-seam list may change; consumers must not rely on it
  (enforced in spirit by naming and documentation, and pinned for *our*
  tests by the API contract test).
- Any future breaking change must follow the STOP protocol in
  docs/api-stability.md (document behavior, problem, alternatives,
  migration path, compatibility impact).
