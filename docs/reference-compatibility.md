# Reference Compatibility Audit (Phase 17)

Final high-level differential audit of SuroMesh (Go) against
`reference/SPlusthon` (Python). Per-phase differential evidence lives in the
phase reports and their docs; this document records the *semantic* verdict
per subsystem and classifies every meaningful deviation:

| Class | Meaning |
|---|---|
| REFERENCE-PARITY | Same observable semantics, evidenced by differential tests |
| GO-IDIOMATIC-DEVIATION | Different shape because Go is not Python; semantics preserved |
| INTENTIONAL-SCOPE | Deliberately not ported (feature-scope decision) |
| SCHEMA-BLOCKED | Reference has it; Layer 182 schema lacks the required RPCs |
| UNVERIFIED | Requires a real Soroush Plus server; NOT PERFORMED — no real Soroush Plus credentials available |

The Python reference is the behavioral oracle; its tree is untouched
(0 modified files) throughout the project.

## Core SDK semantics — REFERENCE-PARITY

- TL marshaling/unmarshaling over Layer 182 (1,684 generated constructors);
  manual constructors (gzip_packed, msg_container, rpc_result) hand-ported.
- UTF-16 code-unit text/entity offsets, including the surrogate rule
  (helpers.py:39-45, markdown.py:62) — golden vectors generated by
  *executing* the Python reference (tools/vectors).
- `parse_phone` normalization — table-driven differential tests.

## Authentication semantics — REFERENCE-PARITY (flow) / UNVERIFIED (server behavior)

- auth.exportAuthorization/importAuthorization flow, DH key exchange,
  msg_ids and salts: ported with the same state machine shape.
- SRP/2FA: `compute_check` is a line-faithful port of password.py:136-194
  (PBKDF2-HMAC-SHA512 ×100,000; 2048-bit prime checks; M1 construction).
  Golden vectors for A/M1 are byte-compared against the executed reference.
- Session reuse after restart without re-auth: same rule as the reference's
  authorized-flag semantics (connection loss ≠ logout; 401 = revocation).
- UNVERIFIED: only the live server's actual code/salt/SRP parameter
  behavior.

## Session semantics — REFERENCE-PARITY

- StringSession: byte-compatible with the reference (both v1 layouts),
  differential-tested.
- Persistent update state (pts/qts/seq/date + channel pts) mirrors the
  reference's SessionState/ChannelState split (session.py), with the
  Go side persisting MessageBox state through the same field meanings.
- Deviation (GO-IDIOMATIC-DEVIATION): the reference keeps transient seq
  counters in its session object; SuroMesh deliberately does not persist
  transport-internal session IDs/sequence numbers — they are per-connection
  state here (docs/session.md).

## Peer semantics — REFERENCE-PARITY

- Entity cache is server-authoritative: access hashes are never fabricated;
  unknown entities raise the typed "access hash unavailable" error (matches
  the reference raising ValueError-derived errors instead of inventing
  hashes).
- Resolve cascade (self → username → cache → marked ID) mirrors
  get_input_entity's cascade order; `ResolveMarkedID` reproduces the
  +user/-chat/-channel marking rule.
- GO-IDIOMATIC-DEVIATION: the reference exposes entity string/bytes
  serialization (`Entity.from_str/from_bytes`); SuroMesh exposes the same
  capability through the persisted session + cache instead of a per-entity
  wire format. Same capability, different carrier.

## Message semantics — REFERENCE-PARITY

- `_get_response_message` port (messageparse.py:113-231): random_id→id
  mapping, edit id-matching, short-form synthesis, nil holes for unmapped
  IDs.
- Message identity: MessageKey{Peer, ID} — the Go formulation of the
  reference's (peer, id) pairing; IDs are never treated as globally unique.
- Service messages: the digest keeps everything the reference keeps (only
  MessageEmpty is skipped; messages.py:196-198) and represents service
  payloads as typed `ServiceInfo` (GO-IDIOMATIC-DEVIATION in *representation*
  only: Go models actions as flags + kind instead of Python object identity).

## Update semantics — REFERENCE-PARITY

- MessageBox is a faithful port of `_updates/messagebox.py`: pts/qts/seq
  gates including the Python truthiness rule (pts=0 means "no information",
  not ordering), possible-gap buffers (100 ms self-resolution, bounded
  256 items), difference/channel-difference recovery, batch ordering by
  pts−pts_count.
- Own-update semantics: update-family RPC results advance state without
  re-dispatching to subscribers (_store_own_updates,
  mtprotosender.py:744-790) — no duplicate events.
- GO-IDIOMATIC-DEVIATION: subscribers receive domain events through a
  bounded queue with explicit overflow policy instead of Python's unbounded
  in-loop dispatch; ordering guarantees are identical.

## Media semantics — REFERENCE-PARITY

- Upload/download part sizes, big-file thresholds, file-reference expiry
  (FILE_REFERENCE_EXPIRED → refetch) follow the reference's transfer rules;
  memory profile is O(part) streaming rather than whole-file buffering
  (INTENTIONAL-SCOPE improvement, documented in docs/transfer.md).
- Canonical media classification path (single conversion function, same
  input→kind mapping as the reference's document/photo branches).

## Pagination semantics — REFERENCE-PARITY

- Dialogs/history/search/global-search use the reference's limit/offset
  rules, termination on short pages, and identical "id ≤ max_id"
  exclusion semantics. Iterators are caller-owned cancellation points
  (GO-IDIOMATIC-DEVIATION: `Next()` + `Err()` instead of Python generators;
  semantics preserved and covered by pagination tests).

## Error semantics — REFERENCE-PARITY

- RPC error strings map to typed/sentinel errors; FLOOD_WAIT carries the
  numeric wait and the same auto-retry threshold rule as the reference
  (flood_sleep_threshold equivalent, docs/retry-policy.md).
- GO-IDIOMATIC-DEVIATION: the reference raises Python exceptions; SuroMesh
  returns `error` values designed for `errors.Is/As` (docs/error-contract.md).
  Callers never parse strings.

## Lifecycle semantics — REFERENCE-PARITY

- Unauthorized → code → (password) → authorized → (revoked) state machine
  mirrors the reference's authorization flow; logout invalidates; close is
  terminal (docs/lifecycle-contract.md).
- GO-IDIOMATIC-DEVIATION: SuroMesh adds an explicit terminal `Close` barrier
  with bounded shutdown the reference does not have (asyncio cancellation
  plays this role loosely).

## INTENTIONAL-SCOPE (not ported, by decision)

Reactions, participants enumeration/admin operations, folders, invite-link
management, sponsored messages, payments, stories, bot API surface — P2/P3
in docs/phase16-capability-matrix.md. Feature count was not the Phase 17
goal; contract quality was.

## SCHEMA-BLOCKED

Drafts: the reference implements drafts over getAllDrafts/setDraftMessage/
clearAllDrafts; Layer 182 declares `updateDraftMessage` but none of those
RPCs (verified in tl/schema/api.tl; docs/drafts.md).

## UNVERIFIED (live-server only)

Everything in the UNVERIFIED rows above plus: real salt/alt-salt rotation
cadence, real FLOOD_WAIT distributions, real file-reference lifetimes,
real DC migration behavior. All confidence otherwise comes from
differential tests against the executed Python reference, deterministic
fake servers over the real transport/crypto/RPC/TL stack, fuzzing, race
detection, stress/soak and failure injection. Live validation remains:
**NOT PERFORMED — no real Soroush Plus credentials available.**
